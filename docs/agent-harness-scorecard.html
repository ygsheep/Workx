未闭环当前剩余的真实缺口
  • 🔴 CI 硬门禁存在 flaky 误拦（#118） — 同一用例 server: ring buffer replays missed events on reconnect 在 8 次 CI 首次运行中失败 3 次（37.5%），同 commit 重跑即由红转绿。
    → 根因：island_server.cpp:122-156 的 accept 循环里 handle_connection() 阻塞，而 transport_posix.cpp:105-115 在 accept() 成功后立刻关闭监听端点 → 整个服务连接期间端点上没有监听者，重连只能靠 connect() 的 600ms 固定重试（6×100ms）撞运气。次要缺陷：测试 read_until 在 read 立即失败时不 break，空转满 3 秒，掩盖真因。
    → 建议：让 listen socket 生命周期内保持开放（AF_UNIX 常规做法），从根本上消除窗口。见 docs/p0-test-plan.md 阶段 6.3 / #118。
  • #78 行为统计验收口径未实测 — 原始验收标准是「10 个任务中 agent 结束前实际执行过测试/构建命令的比例 ≥90%」。单测只能证明门禁接线与判定正确，证不了真实任务下的行为。追踪见 #117，随首轮跑分采集。
  • 写得出来 ≠ 已经跑分 — CI 跑的是单元测试，不是评测基准。「评测与迭代 45 / 100」衡量的是有没有接 Terminal-Bench / SWE-bench 这类集。下一步：写 Harbor adapter，跑 terminal-bench@2.0 30 题 × 3 次子集。
  • #106 Windows ctest 中文测试名 — 196 / 1319 必然失败（与该批次含中文名用例数精确吻合）。ctest 把中文测试名当过滤参数传给测试进程时 argv 被 GBK 破坏。仅影响 Windows 本地，不阻塞已生效的 Linux 硬门禁。
