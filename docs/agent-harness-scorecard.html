未闭环当前剩余的真实缺口
  • 🔴🔴 #173（P0）BashTool 超时判定滞后约 379s — 请求 timeout=600000，实际 duration=979084ms 才生效。分层证据：react_loop.cpp:1609（ReAct 观测 979s）vs executor.h:287（工具内部 939s）vs executor.h:351（elapsed=978993）。
    ⚠️ <error>Command timed out</error> 只在 stream.jsonl 的 observation 里，run.log grep 该串 = 0 —— 别据此误判「没超时」。当前优先级最高。
  • 🔴 #174（P1）主推理 max_tokens 无上限 — chat_types.h:91 默认 -1，且 openai_adapter.cpp:240 仅在 >0 时才写该字段 → OpenAI 兼容请求不带上限（anthropic 侧有 :4096 兜底）。实证：adaptive 单轮生成 65536 tokens / 361s，烧掉约 79% 墙钟预算。
  • 🔴 #117 / #132 验证口径未达标 — 原始标准「结束前执行过测试/构建命令的比例 ≥90%」，首轮实测 6.7%（1/15）。
    ⚠️ 别误读成「agent 不验证」：它确实用 python3 -c / od -c / probe*.sh 在自检，问题是验证行为没规范化成可识别的构建/测试命令。更根本的是 verifier 测试跑在独立容器，agent 拿不到 tests/，故该口径在「空目录做题」场景先天不适用 → #132「口径分场景」尚未拍板。
  • 🔴 #118 island 重连 flaky — 同一用例 server: ring buffer replays missed events on reconnect 在 8 次 CI 首次运行中失败 3 次（37.5%），同 commit 重跑即翻转。根因：transport_posix.cpp:105-115 在 accept() 成功后立刻关闭监听端点 → 整个服务期间端点上没有监听者。
  • ⚠️ 4/20 轨迹为 0 字节（观测盲区） — agent 撞超时被强杀 → 容器销毁 → tee 的 stream 没取回。这 4 个不是「没验证」，是「不知道它做了什么」。讽刺的是：跑得最久、最可能撞超时的题恰恰最看不到。
  • ⚠️ 分数口径仍不对齐 HarnessTax — 仍是 -k 1（无置信区间）、无 Claude/GPT 对照组、选题是容量排除后按字母序取前 20（非随机）；本批还用了预装 9 题依赖的副本数据集。能说的是「修完之后同一批题 9 → 15」，不是「提分 30 个点」。
  • #175（P3）/ #176 自身（P2） — 产物采集 compose cp 相对路径报错（Windows 下靠 engine cp 重试兜底，本 job 命中 21 处）；建议采集侧分列 env_setup_ms / solve_ms，把「环境自建耗时」显式量出来。

待办 E
修复 island flaky（#118）

让 listen socket 在整个生命周期保持开放，从根本上消除重连窗口；并让测试的 read_until 在 read 立即失败时 break，不再空转满 3 秒掩盖真因。

评分口径提醒：同一模型换 harness，Terminal-Bench 可摆动 3–5 分，SWE-bench 可达 10–20 分；HarnessTax 发现 harness 更影响成本（最高 5 倍）而非成功率 —— 所以最终要画成本–成功率 Pareto 前沿，只看成功率会奖励「烧钱换分」。
